# Модуль RNG (Генераторы псевдослучайных чисел и распределений)

> Ответственный: Шаимов Богдан  
> Состояние: разработан в ветке `feat/RNG-001-M1-protocols` (v2.0.2), проверен модульными тестами  
> База для слияния: `dev` | Обновлено: `2026-11-20`

## 1. Назначение

Модуль `RNG` отвечает за генерацию псевдослучайных последовательностей и случайных величин с заданными распределениями для симулятора планировщика беспроводной сети (`PyScheduler`). Модуль поддерживает работу с изолированными потоками (`stream_idx`), централизованным реестром потоков `StreamAllocator` по ключу `(domain, purpose, entity_id)` и независимыми прогонами (`run_idx`), что обеспечивает строгую повторяемость экспериментов. Математическая генерация изолирована от остального кода симулятора статическими протоколами (`typing.Protocol`).

## 2. Границы ответственности

**Делает:**
- Задаёт статические контракты (`typing.Protocol`): внутренний `UniformEngine` (для математических ядер) и внешний `RandomProvider` (фасад распределений для моделей).
- Генерирует детерминированные числа на строгом полуинтервале $[0.0, 1.0)$ с помощью двух стратегий:
  - `RngStream` (`MRG32k3a`): реализация по спецификации P. L'Ecuyer et al. (2002), побитово совместимая с `ns-3`.
  - `PhiloxStream` (`Philox4x64`): 64-битный counter-based генератор (10 раундов) с нормализацией по стандарту IEEE-754 (через битовый сдвиг мантиссы).
- Предоставляет фасад `RandomGenerator` для извлечения случайных величин: равномерного (`uniform`), нормального (`normal`, полярный метод Бокса — Мюллера с кэшированием второго значения), экспоненциального (`exponential`) и дискретного равновероятного (`get_integer`) распределений.
- Предоставляет реестр `StreamAllocator` для детерминированной выдачи изолированных генераторов по ключу `(domain, purpose, entity_id)` с защитой от повторного захвата одного потока разными потребителями.
- Выполняет строгую валидацию входных параметров и защиту граничных случаев: запрет `bool`, `NaN`, `±Inf`, контроль верхних границ `seed <= 4294944442`, `stream_idx <= 2^63 - 1`, `run_idx <= 2^51` ($2^{127} / 2^{76} = 2^{51}$), защиту от переполнения `float64` и округления верхней границы в `uniform()`, аналитический расчёт усечённого экспоненциального распределения при `bound > 0`, защиту от зависания цикла отбраковки в `normal()` (`bound <= 0` при `variance > 0`, слишком малый `bound / std` и лимит попыток) и точный целочисленный отбор в `get_integer()` без потери точности выше $2^{53}$.

**Не делает:**
- **Не считывает данные из файлов.** Механика предзаписанных трасс (`DataStream`) исключена из модуля для проектирования в рамках отдельной будущей фичи `FEAT-RNG-003`.
- Не рассчитывает физику движения абонентов, состояние радиоканала и сетевой трафик (это задача соответствующих моделей, которым генератор передаётся через Dependency Injection).

## 3. Происхождение алгоритмов и лицензирование

- **Портированные из ns-3 компоненты:** математическое ядро `RngStream` (`MRG32k3a`), матрицы переходов и предвычисленный кэш двоичных степеней, а также базовые формулы генерации распределений перенесены из `ns-3` (лицензия GPLv2) для обеспечения побитовой совместимости при кросс-валидации.
- **Самостоятельно разработанные компоненты PyScheduler:** ядро `PhiloxStream` (`Philox4x64`), интерфейсы `UniformEngine` и `RandomProvider`, строгая валидация параметров (`NaN`/`Inf`, границы индексов и `seed`), защита от переполнения `float64` и зависания циклов отбраковки, потокобезопасная инициализация кэша матриц, точный целочисленный `get_integer()`, а также реестр потоков `StreamAllocator`.
- **План по лицензионной чистоте:** в рамках следующей задачи заимствованные математические блоки `MRG32k3a` и распределений будут переписаны заново по открытой математической спецификации P. L'Ecuyer (1999, 2002) и стандартным численным методам. Текущая валидация по эталону `ns-3` сохранится как набор побитовых проверок для ядра `MRG32k3a`.

## 4. Преимущества реализации в PyScheduler

1. **Защита от некорректных параметров и зависаний:** все входные параметры проверяются на `NaN` и бесконечности. В `normal()` отклоняются недопустимые и слишком узкие границы (`bound <= 0` при `variance > 0`, `bound / std < 1e-6`), а число попыток отбора ограничено с выбросом `ValueError`. В `exponential()` при `bound > 0` используется прямая формула усечённого распределения за $O(1)$ без цикла отбора, что исключает зависание на малых границах.
2. **Точная целочисленная арифметика и потокобезопасный кэш матриц:** модульное умножение `(a * s + c) mod m` и последовательное возведение матриц перехода в степень выполняются в точных целых числах Python. Построение кэша матриц при первом обращении защищено блокировкой (`threading.Lock`) и сохраняется в виде неизменяемых кортежей (`tuple`), что исключает гонки и дублирование записей при параллельных первых вызовах.
3. **Явный Dependency Injection и сменные математические ядра:** модели получают генератор через единый интерфейс `RandomProvider` без прямых вызовов глобального `np.random`, а ядро генерации переключается между `MRG32k3a` и `Philox4x64`.
4. **Независимость потоков от порядка регистрации:** `StreamAllocator` вычисляет индекс потока напрямую из нормализованного ключа `(domain, purpose, entity_id)` с помощью хеш-функции (`blake2b`) и запрещает повторную выдачу уже занятого ключа. Перестановка компонентов или добавление новых процессов не сдвигают последовательности существующих моделей.

## 5. Входы, выходы и зависимости

| Вход | Откуда | Формат / смысл |
|---|---|---|
| `seed` | Вызывающий модуль / ядро | `int` в диапазоне `[0, 4294944442]` (`0` заменяется на `12345`; строго `< m2 = 4294944443`). Запрещены отрицательные числа и `bool`. |
| `base_stream_idx` / `stream_idx` | `StreamAllocator` / ядро | `int` в диапазоне `[0, 2^63 - 1]` — индекс изолированного потока. |
| `run_idx` | Вызывающий модуль / ядро | `int` в диапазоне `[1, 2^51]` — номер независимого прогона симуляции ($2^{127} / 2^{76} = 2^{51}$ непересекающихся прогонов на поток). |
| `engine` | Вызывающий модуль / ядро | `str` (`'MRG32k3a'`, `'Philox'`) — выбор математической стратегии. |
| `(domain, purpose, entity_id)` | `SimulationManager` | Ключ регистрации уникального потока в `StreamAllocator` (например, `('CHANNEL', 'SHADOW_FADING', 17)`). |
| Параметры распределений | Модели симулятора | `min_val`, `max_val`, `mean`, `variance`, `bound` (строгая фильтрация `NaN`/`Inf` и невалидных границ). |

| Выход | Куда | Формат / смысл |
|---|---|---|
| Базовое число $U(0, 1)$ | `RandomGenerator` | `float` строго в диапазоне $[0.0, 1.0)$ из методов `rand_u01()`. |
| Случайная величина | Модели симулятора | `float` (`uniform`, `normal`, `exponential`) или `int` (`get_integer`). |

**Зависимости:**
- Только встроенная библиотека Python 3.12 (`hashlib`, `json`, `math`, `threading`, `typing`). Внешних зависимостей от других модулей проекта нет.

## 6. Как проверить работу

Модуль запускается и верифицируется автономно локальными модульными тестами из корня проекта:

```bash
pytest test_rng.py -v
```

Тесты проверяют совпадение `MRG32k3a` с эталоном `ns-3`, математические границы `Philox4x64`, отсутствие коллизий между потоками и на границе `run_idx = 2^51` (и коллизию при `2^51 + 1`), корректность `uniform` на широких (`[-1e308, 1e308]`) и соседних `float`-границах, завершение `exponential` и `normal` при малых `bound`, точность и равномерность `get_integer` (включая отрицательные диапазоны и числа $> 2^{53}$), отбраковку `NaN`/`Inf`, потокобезопасность кэша матриц, а также независимость `StreamAllocator` от порядка регистрации и запрет повторного захвата ключа.

## 7. Основные компоненты

| Компонент / Файл `RNG.py` | Назначение | Где используется |
|---|---|---|
| `UniformEngine` (`Protocol`) | Статический контракт ядра генерации ПСЧ с методом `rand_u01()`. | Для проверки соответствия стратегий внутри `RandomGenerator`. |
| `RandomProvider` (`Protocol`) | Статический контракт источника распределений (4 метода без доступа к чужим индексам потоков). | Как аннотация типа в моделях `Mobility`, `Channel`, `Traffic` (DI). |
| `RngStream` | Стратегия `MRG32k3a` с потокобезопасным кэшем матриц перехода для сдвига по потокам и прогонам. | В `RandomGenerator` (по умолчанию `engine='MRG32k3a'`). |
| `PhiloxStream` | Стратегия `Philox4x64` (10 раундов, буфер на 4 числа, нормализация IEEE-754 мантиссы). | В `RandomGenerator` при `engine='Philox'`. |
| `RandomGenerator` | Фасад генерации случайных величин. Инкапсулирует изолированный поток `_stream` и кэш Бокса — Мюллера `_normal_cache`. | Единая точка конфигурации в `SimulationManager` и внедрения в модели. |
| `StreamAllocator` | Реестр и аллокатор потоков по ключу `(domain, purpose, entity_id)` на основе хеширования `blake2b` с правилом единственного владельца. | В `SimulationManager` для выдачи изолированных генераторов подсистемам. |

## 8. Один типичный сценарий

**Сценарий: Выделение потока через StreamAllocator и генерация нормальной величины**
1. Ядро симулятора создаёт `allocator = StreamAllocator(seed=12345, run_idx=1, engine='MRG32k3a')`.
2. Для модели затенения канала абонента UE 17 запрашивается генератор: `rng = allocator.get_provider("CHANNEL", "SHADOW_FADING", entity_id=17)`. Аллокатор нормализует ключ `('CHANNEL', 'SHADOW_FADING', 17)`, вычисляет его детерминированный `stream_idx` через `blake2b`, закрепляет ключ за единственным владельцем и возвращает `RandomGenerator`.
3. Модель вызывает `rng.normal(mean=0.0, variance=64.0, bound=24.0)`.
4. Метод `normal()` проверяет параметры на отсутствие `NaN`/`Inf`, убеждается, что `variance >= 0` и `bound` не слишком мал относительно СКО, инициализирует поток `RngStream`, генерирует пару чисел по методу Бокса — Мюллера, сохраняет второе число в `_normal_cache` и возвращает первое.
