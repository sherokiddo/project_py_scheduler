# План развития модуля MOBILITY_MODEL

> Ответственный: Кутенков Андрей | Обновлено: 2026-10-17

Идентификаторы глобально уникальны: `FEAT-MOB-NNN`. Прежний локальный FEAT-001..004 соответствует FEAT-MOB-001..004; порядковые номера и смысл предложений сохранены. Общая крупная фича — `FEAT-INT-001`, спецификация [INT-MF-001 v1.0](../../integration_report.md). Все интерфейсы в ней — проектные.

## 1. Предложения для своего модуля

### FEAT-MOB-001 — Единый входной DTO положения/скорости/направления и dt
- **Статус:** идея; черновик уточнён по коду, согласование изменений не получено.
- **Проблема сейчас:** Модель получает живой UserEquipment; шаг выражен как time_ms и результат применяется в UserEquipment.UPD_POSITION. Это связывает расчёт с объектом симулятора.
- **Цель:** Адаптер движения принимает снимок UE и StepContext и возвращает MobilityResult без скрытого применения к UE.
- **Предлагаемое изменение:** Адаптер движения принимает снимок UE и StepContext и возвращает MobilityResult без скрытого применения к UE.
- **Входит / не входит:** собственный адаптер, внутреннее состояние и тесты MOBILITY_MODEL; изменения SimulationManager, RNG и UE_MODULE выполняют их владельцы. Переписывание математических формул не входит.
- **Входы и выходы:** черновик INT-MF-001, разделы 3–6; адаптер принимает StepContext и снимок UE, выдаёт результат своего модуля. Для file вход — готовые записи; для model — параметры и выделенный RNG.
- **Зависимости:** SimulationManager — время и маршрутизация; UE_MODULE — ID и применение; RNG — воспроизводимые потоки. Запросы перечислены ниже в разделе 2 настоящего файла.
- **Шаги:** 1) использовать выполненную сверку исходников и результаты audit; 2) согласовать соответствующую часть INT-MF-001; 3) реализовать собственный адаптер/изменение; 4) выполнить проверку ниже и общую интеграционную матрицу.
- **Проверка готовности:** На карте 0..100 м UE=(10,10), v=1 м/с, угол=0, dt=1000 мс: ожидается (11,10); базовый сценарий уже выполнен, адаптер должен его сохранить.
- **Риски и вопросы:** действующие сигнатуры проверены; до изменения сохранить поведение базового сценария и согласовать правила времени, RNG и lifecycle.
- **Ссылки:** [спецификация](../../integration_report.md), [ревизия](audit.md).
