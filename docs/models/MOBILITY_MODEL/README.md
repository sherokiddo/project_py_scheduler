## 1. Назначение
Модели движения пользовательских устройств: RandomWalk, RandomWaypoint, RandomDirection, GaussMarkov и DiagonalWalk.

## 2. Границы ответственности
**Делает:** Модели движения пользовательских устройств: RandomWalk, RandomWaypoint, RandomDirection, GaussMarkov и DiagonalWalk.

**Не делает:** не управляет временем симуляции, выбором model/file и жизненным циклом UE. Реестра model/file, файлового адаптера готовых результатов и отдельного RNG API в просмотренных исходниках нет; они относятся к проектируемой интеграции.

## 3. Входы, выходы и зависимости
| Вход | Откуда | Формат / смысл |
|---|---|---|
| Параметры и состояние | SimulationManager → UECollection → UserEquipment | UE с координатами и диапазоном скоростей; границы карты; длительность шага `time_ms` в мс; для DiagonalWalk — BS и пауза. |

| Выход | Куда | Формат / смысл |
|---|---|---|
| Результат | Вызывающий код | Кортеж `(position, velocity, direction)`: координаты в м, скорость в м/с, направление в рад. |

Зависимости: `numpy`, `inspect`, `typing.Tuple`, `BS_MODULE.BaseStation`, `UE_MODULE.UserEquipment`; границы через MapBorders. Импорты проверены.

## 4. Как проверить работу

Из каталога `PyScheduler`:

```bash
python -m unittest discover -s tests/mobility_module_tests -p test_mobility_module_unit.py -v
python -m unittest discover -s tests/mobility_module_tests -p test_mobility_module_intg.py -v
```

Выполнено: **27 unit + 36 integration тестов, все прошли**. Интеграционные тесты используют реальные UserEquipment/UECollection и тестовые BS; это не запуск полной сети.

Минимальная проверка реальной модели (из `PyScheduler`, Python):

```python
from types import SimpleNamespace
from MOBILITY_MODEL import MapBorders, MobilityInterface
MapBorders.reset()
MapBorders(0,100,0,100)
ue=SimpleNamespace(position=(10.,10.),velocity=1.,direction=0.,velocity_min=1.,velocity_max=1.)
model=MobilityInterface.create("RandomWalk",ue=ue)
print(model.update(1000)[:2])
```

Получено: `((11.0, 10.0), 1.0)`. Это проверяет перемещение на 1 м за 1 с, а не все модели/границы.

#### RandomWalkModel

Случайное блуждание: очередной шаг по текущим скорости и направлению, затем выбор новых значений.

##### `__init__()`

**Сигнатура по коду:** `__init__(self, ue: UserEquipment, **kwargs)`.
**Источник:** `PyScheduler/MOBILITY_MODEL.py::RandomWalkModel.__init__`.

**Роль:** Инициализация.

**Как работает:** Запускает инициализацию базовой модели и ставит флаг первого перемещения.

**Принимает:** `ue` — Объект UE с координатами, скоростью и параметрами движения (UserEquipment); `**kwargs` — дополнительные параметры конкретной модели.

**Возвращает:** `None`; сохраняет состояние движения.

##### `update()`

**Сигнатура по коду:** `update(self, time_ms: int, **kwargs)`.
**Источник:** `PyScheduler/MOBILITY_MODEL.py::RandomWalkModel.update`.

**Роль:** Основная операция.

**Как работает:** Смещает UE на `v·Δt` по текущему углу, отражает координаты при выходе за границы и задаёт следующую случайную скорость; угол выбирается заново на шаге без столкновения.

**Возвращает:** `(новые координаты, новая скорость в м/с, угол в рад)`.

**Особенность:** Направление и скорость, выбранные в конце вызова, используются на следующем шаге; перемещение текущего шага рассчитано по старым значениям UE.

Движение от одной случайной цели к другой с остановками.

**Сигнатура по коду:** `__init__(self, ue: UserEquipment, **kwargs)`.

**Роль:** Внутренний метод.

**Как работает:** Выбирает координаты цели внутри карты, скорость в диапазоне UE и вычисляет направление к цели через `arctan2`.

**Принимает:**

- `current_position` — Координаты UE на плоскости (Tuple[float, float]).
- `velocity_min` — Нижняя граница скорости, м/с (float).
- `velocity_max` — Верхняя граница скорости, м/с (float).

**Возвращает:** `(цель, скорость, направление, False)`.

##### `update()`

**Сигнатура по коду:** `update(self, time_ms: int, **kwargs)`.
**Источник:** `PyScheduler/MOBILITY_MODEL.py::RandomWaypointModel.update`.

**Роль:** Основная операция.

**Как работает:** Во время паузы удерживает координаты. После паузы выбирает новую цель; в движении либо доходит до цели за текущий шаг и останавливается, либо проходит часть пути.

**Принимает:** `time_ms` — Длительность шага, мс (int); `**kwargs` — дополнительные параметры конкретной модели.

**Возвращает:** `(координаты, скорость, направление)`; изменяет таймер и текущую цель.

#### GaussMarkovModel

Связанное по времени движение: скорость и направление зависят от предыдущих значений.

##### `__init__()`

**Сигнатура по коду:** `__init__(self, ue: UserEquipment, alpha: float=0.75, boundary_threshold: float=5.0, **kwargs)`.
**Источник:** `PyScheduler/MOBILITY_MODEL.py::GaussMarkovModel.__init__`.

**Роль:** Инициализация.

**Как работает:** Сохраняет коэффициент памяти `alpha`, расстояние защитной зоны у границы и средние скорость/направление.

**Принимает:**

- `ue` — Объект UE с координатами, скоростью и параметрами движения (UserEquipment).
- `alpha` — Коэффициент памяти Gauss–Markov (float); по умолчанию `0.75`.
- `boundary_threshold` — Ширина защитной полосы вдоль границы карты, м (float); по умолчанию `5.0`.
- `**kwargs` — дополнительные параметры конкретной модели.

**Возвращает:** `None`; устанавливает параметры случайного процесса.

##### `update()`

**Сигнатура по коду:** `update(self, time_ms: int, **kwargs)`.
**Источник:** `PyScheduler/MOBILITY_MODEL.py::GaussMarkovModel.update`.

**Роль:** Основная операция.

**Как работает:** Смешивает прежние и средние скорость/угол с нормальным шумом; около краёв направляет UE внутрь области; затем перемещает UE и отражает координаты при выходе за карту.

**Принимает:** `time_ms` — Длительность шага, мс (int); `**kwargs` — дополнительные параметры конкретной модели.

**Возвращает:** `(новые координаты, новая скорость, новый угол)`; сохраняет состояние на следующий шаг.

**Особенность:** Нормальный шум способен сделать скорость отрицательной: перед перемещением ограничение скорости не применяется.

**Сигнатура по коду:** `_choose_new_destination(self, current_position: Tuple[float, float], velocity_min: float, velocity_max: float, is_first_move: bool)`.
**Источник:** `PyScheduler/MOBILITY_MODEL.py::DiagonalWalkModel._choose_new_destination`.

**Роль:** Внутренний метод.

**Как работает:** Строит центрально-симметричную точку `(2·bs_x − x, 2·bs_y − y)`, запоминает её и выбирает максимальную скорость UE.

**Принимает:**

- `current_position` — Координаты UE на плоскости (Tuple[float, float]).
- `velocity_min` — Нижняя граница скорости, м/с (float).
- `velocity_max` — Верхняя граница скорости, м/с (float).
- `is_first_move` — Признак первого движения (bool).

**Возвращает:** `(цель, максимальная скорость, 0.0, False, 0.0, 0.0)`.

**Особенность:** При совпадении UE и BS рассчитанная цель остаётся в центре; `velocity_min` не участвует в выборе скорости.

##### `update()`

**Сигнатура по коду:** `update(self, time_ms: int, **kwargs)`.
**Источник:** `PyScheduler/MOBILITY_MODEL.py::DiagonalWalkModel.update`.

**Роль:** Основная операция.

**Как работает:** При необходимости строит симметричную цель, направляется к ней по `arctan2`; после прибытия включает паузу, затем обновляет цель.

**Принимает:** `time_ms` — Длительность шага, мс (int); `**kwargs` — дополнительные параметры конкретной модели.

**Возвращает:** `(координаты, скорость, направление)`; обновляет паузу и цель.


### Связь с другими частями симулятора

`UE_MODULE.py` хранит текущее положение UE; конкретная модель использует это состояние и вычисляет значения следующего шага. Настройки границ находятся в `MapBorders`.

## 6. Один типичный сценарий

1. `SimulationManager.run_tti(current_time)` при кратности `update_interval` вызывает `UECollection.UPDATE_ALL_USERS`.
2. Коллекция проверяет кратность `mobility_update_interval` и вызывает `UserEquipment.UPD_POSITION(mob_interval)`.
3. UE вызывает `self.mobility_model.update(time_ms=update_interval)` у конкретной модели, получает `(position,velocity,direction)` и применяет к своим полям; затем пересчитывает расстояния до BS.

Фабрика `MobilityInterface.create` используется при `UserEquipment.SET_MOBILITY_MODEL`; отдельного промежуточного делегирования базового update в потомка нет. Default-интервалы: общий 1 мс, Mobility 500 мс. Обновление также происходит при current_time=0; это поведение AS-IS, не контракт будущего конечного снимка TTI.

## 7. Ограничения и открытые вопросы
- Статусы замечаний уточнены в audit.md: различаются воспроизведённые ошибки, подтверждённые конструкции кода и несогласованные архитектурные решения. Наличие метода не означает прохождение всех его ветвей.
