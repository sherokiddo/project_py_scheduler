## 2. Карточки наблюдений

### AUD-001 — HARQ не включён в основной цикл планирования

- **Объект:** `PyScheduler/SCHEDULER.py::SchedulerInterface.__init__`,
  `schedule`, `_get_harq_retransmissions`, `_filter_eligible_ues`.
- **Категория:** технический долг: незавершённая функциональность.
- **Наблюдение:** конструктор устанавливает `harq_manager = None`. `_get_harq_retransmissions()` делегирует запрос подключённому менеджеру либо возвращает `[]`, но из `schedule()` не вызывается. Проверка занятости процессов присутствует только в комментариях. Работающего цикла ACK/NACK в файле нет.
- **Доказательство:** чтение перечисленных методов; Контрольный вызов метода при `harq_manager=None` вернул `[]`.
- **Влияние:** текущая симуляция не моделирует повторы через эти точки расширения. Простого присваивания менеджера недостаточно для подключения HARQ к `schedule()`. Отсутствие функциональности не классифицируется как ошибка сценария без HARQ.
- **Как проверить:** для будущей интеграции использовать менеджер-заглушку, возвращающий одну повторную передачу, и проверить, что основной цикл действительно запрашивает её, учитывает занятый процесс и выдаёт ресурсы согласно контракту.
- **Статус:** подтверждено по коду и контрольным вызовом.
- **Связь:** обсуждаемая FEAT-TB-001; отдельный контракт HARQ в
  [features.md](features.md) требуется дополнить. Issue/PR пока нет.
