# План перехода к самостоятельному AMC

> Актуализация 2026-11-01: [исправления по ревью AMC](AMC_REVIEW_FIXES.md) имеют приоритет над прежними предложениями ниже. Legacy-статистика и конструктор сохранены; TB вынесен в TRANSPORT_BLOCK.py, TBS исправлен на 88 в I_TBS=6/N_PRB=1, добавлен интерфейс политики MCS. AMC_METRICS и удаление get_stats сейчас не планируются.


Дата: 2026-10-30. Основа: [SPEC-FEAT-AMC-001](SPEC-FEAT-AMC-001.md). Статусы: [ROADMAP-AMC](ROADMAP-AMC.md).

## 1. Что уже выполнено

Класс `AdaptiveModulationAndCoding` и две таблицы спектральной эффективности перенесены из SCHEDULER.py в [AMC.py](../PyScheduler/AMC.py). Прежний импорт класса через SCHEDULER сохранён. Тело класса и его интерфейс не изменены.

AMC по-прежнему принимает Scheduler в конструкторе, читает `pcfich` через PDCCHManager и собирает статистику через состояние Scheduler/UE. TransportBlock и расчёт TBS остаются в SCHEDULER.py. AmcConfig, AMC_METRICS, get_amc_stats и адаптер пока отсутствуют.

**Вынос выполнен; архитектурная самостоятельность ещё не достигнута.**

## 3. Предлагаемый интерфейс

```python
@dataclass()
class AmcConfig:
    control_symbols: int = 2

class AdaptiveModulationAndCoding:
    def __init__(self, config: AmcConfig | None = None):
        self.config = config if config is not None else AmcConfig()

    def get_mcs_from_cqi(self, cqi: int) -> int: ...
    def GET_BITS_PER_RB(self, cqi: int, n_ports: int = 1) -> int: ...
```

Создание у владельца конфигурации, после инициализации PDCCHManager:

```python
self.amc = AdaptiveModulationAndCoding(
    AmcConfig(control_symbols=self.pdcch_manager.pcfich)
)
```

Проверка допустимости управляющей области для полосы остаётся у конфигурации/PDCCHManager. Вычислительный AMC получает только значение. Самостоятельность не требует менять численные формулы или правила выбора MCS.

## 4. Статистика и ответственность

Scheduler формирует снимок в момент запроса, копируя UE ID, число RB, capacity в битах, переданные биты, throughput в бит/с, WB/SB-CQI и SINR. SB-CQI копируется в tuple. Отсутствие CQI сохраняется отдельно от CQI=0. Сборщик получает только значения и возвращает прежний словарь метрик.

Нужно сохранить прежнюю фильтрацию пользователей, нулевые записи throughput для пропущенных пользователей, округление и смысл знаменателей средних. Если для этого нужны исходные идентификаторы всех пользователей, снимок должен содержать их отдельным tuple. Изменение этих правил не является частью переноса.

Снимок содержит признак ready: отсутствие завершённого шага отличается от пустого завершённого шага. Поведение до первого schedule определяется отдельно и проверяется тестом; оно не считается доказанным существующей регрессией.

Оба вызова в SimulationManager заменяются вместе с добавлением get_amc_stats. Только после этого старый метод удаляется из AMC. Сборщик статистики не получает Scheduler через конструктор или замыкание.

## 5. TBS и интерфейс Тимура

TBS остаётся отдельным расширением внутри спецификации: добавить чистую функцию `get_tbs_bits(mcs, rb)` и делегировать ей `TransportBlock.determination_of_size_TB()`. Вход — MCS 0–28 и целое число PRB 1–110, выход — биты. Bool и неверные типы/диапазоны отклоняются. Ошибка не должна менять сохранённый tbs.

Для устранения обратной ссылки на Scheduler этот шаг не обязателен. Перенос самого TransportBlock в AMC.py остаётся предложением расширенного плана, а не выполненной работой и не условием самостоятельности AMC. Переключение бюджетов _process_buffers на таблицу — отдельное изменение поведения FEAT-TB-001.

У Тимура предложен AmcView.bits_per_rb(cqi). Адаптер может делегировать его существующему методу AMC. Добавление mcs_from_cqi/tbs_bits в общий view и размещение адаптера требуется согласовать; согласование ещё не состоялось.

## 6. Порядок реализации и приёмка

Сохранены идентификаторы A0–A5 из спецификации. Выполненный механический перенос обозначен E0, он не закрывает A3.

| Этап | Действие | Обязательные проверки |
|---|---|---|
| E0 — выполнен | Класс и таблицы в AMC.py, прежний интерфейс сохранён | 69 тестов прошли; AST класса и остального Scheduler совпал с исходным |
| A0 — частично | Дополнить эталоны baseline назначений и полной симуляции | Два воспроизводимых запуска с одинаковыми входами; база сравнения и исключения |
| A1 — план расширения | Единый TBS-калькулятор и делегирование TB | Контрольные ячейки, 3190 сочетаний, ошибки, общая регрессия |
| A2 — план самостоятельности | Снимок, агрегатор, get_amc_stats и оба потребителя | Все ключи/значения, пустой/неготовый шаг, момент запроса, общая регрессия |
| A3 — план самостоятельности | AmcConfig, новый конструктор, удаление self.scheduler/get_stats | Численное совпадение, конфигурация, импорты, отсутствие обратных зависимостей, общая регрессия |
| A4 — план интеграции | Согласованный AmcViewAdapter | Делегирование и регрессия каждой затронутой стратегии |
| A5 — итог | Проверка всех потребителей и актуализация AS-IS | Полная R-батарея спецификации и интеграционный сценарий |

После каждого изменения рабочего кода проверять назначения PRB/CCE, очереди, переданные биты, throughput/EWMA и статистику относительно A0. Не обновлять эталоны для скрытия расхождений. Каждый этап фиксировать с командой, результатом, допустимыми различиями и откатом.

Подготовленные 69 проверок не заменяют тесты всего pipeline, QoS и 5000 TTI. Полная интеграционная регрессия пока не подтверждена.

```sh
.venv/bin/python -B -m pytest -q -p no:cacheprovider PyScheduler/tests/amc_tests
```

Режим по умолчанию называется legacy: это прежний интерфейс уже вынесенного AMC. Подтверждённый результат после переноса — **69 passed**. Один тест проверяет все 3190 сочетаний MCS/PRB по зафиксированной последовательности; это контроль отсутствия изменений, не проверка каждой ячейки по стандарту.

После реализации расширенного целевого контракта:

```sh
.venv/bin/python -B -m pytest -q -p no:cacheprovider PyScheduler/tests/amc_tests --amc-target=extracted
.venv/bin/python -B -m pytest -q -p no:cacheprovider PyScheduler/tests/amc_tests/contract_extracted.py
```

Эти команды пока не являются пройденной приёмкой: AmcConfig/get_tbs_bits отсутствуют, а контрактный файл также ожидает перенос TB. Для приёмки только самостоятельности следует отдельно запускать относящиеся к ней проверки, не объявляя завершённым TBS-расширение. contract_extracted.py не собирается автоматически: нужен явный запуск. Пропуска недостающего API нет.
